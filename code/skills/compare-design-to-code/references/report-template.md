# 代码设计说明与代码一致性比对报告模板

按实际规模裁剪，但保留可核验基线、双向追溯、关键路径证据、问题和结论边界。不要为填模板虚构代码行为。

## 1. 报告身份与结论

- 报告标识、日期和状态：
- 代码设计说明名称、版本、状态和适用配置：
- 代码仓库或材料包、提交或快照、工作区差异：
- 构建、平台、参数和运行配置：
- 比较范围：
- 总体结论：`CONSISTENT`／`PARTIALLY_CONSISTENT`／`INCONSISTENT`／`INDETERMINATE`。
- 结论依据：
- 限制：未读代码、外部黑盒、缺失生成物、未执行活动和不可核验项。

本结论只评价指定设计与指定实现基线之间的一致性，不证明需求满足、全部运行行为、系统安全或发布资格。

## 3. 正向追溯矩阵

状态使用 `IMPLEMENTED`／`PARTIAL`／`MISSING`／`CONTRADICTED`／`NOT_APPLICABLE`／`UNKNOWN`。复合义务必须能看出各条件和结果的去向。

另列实际执行的命令、平台、配置和结果。未执行的检查只列为建议，不写成观察事实。

## 6. 问题清单

每项使用稳定编号，例如 `DC-001`，并记录：

- 设计位置、代码符号、配置和版本。
- 类型：设计问题／实现遗漏／实现冲突／追溯错误／无依据实现／配置或构建不匹配／代码与注释不一致／证据不足。
- 触发条件、路径可达性和证据性质：静态推导或运行观察。
- 设计预期与实现行为，以及可观察差异。
- 对接口、状态、时序、资源、验证或上游需求的影响。
- 最小处理建议、建议责任人、回归范围和关闭证据。
- 状态：开放／已处理待复查／关闭／保留限制。
