# 航空航天专项检查

用于飞控、姿态控制、航电、任务管理、地面测控及试验支持需求。此文件是检查提示，不是认证规范；适用标准、软件等级和审批责任以项目资料为准。

## 适用性与阶段

先确定任务阶段、运行范围或飞行包线、设备配置、软件职责和故障假设。系统级目标可以通过下层分配落实；不要要求高层需求包含全部代码细节，但应检查分配关系是否明确、当前阶段是否已达到所需成熟度。

## 专项维度

| 维度 | 重点检查与反例方向 |
| --- | --- |
| 任务与模式 | 适用阶段、模式进入退出、禁止转移、指令与故障同时发生时的优先级、控制权限移交 |
| 信号语义 | 单位、坐标系、轴向和符号、姿态表示、量程、精度、时间基准、采样与接收时刻的区别 |
| 数据有效性 | 缺失、陈旧、冻结、失序、重复、偏置、质量标志及不同故障的判别责任 |
| 实时性 | 周期、端到端截止时间、起止事件、检测相位、抖动、多速率交换及预算分配 |
| 初始化与恢复 | 上电、复位、看门狗重启、状态保持、热切换、任务中断和恢复条件 |
| 数值约束 | 数值范围、精度、溢出与非有限值、离散化、累计误差及必要的算法约束 |
| 执行机构 | 饱和、速率限制、反馈不一致、不可用及控制输出边界 |
| 故障策略 | 检测、隔离、降级、恢复、防止反复切换、规定范围内的组合故障及共同依赖 |
| 控制性能 | 指标、评价窗口、初始条件、扰动、不确定性、模型范围和可接受瞬态 |
| 平台与资源 | 调度、CPU、内存、栈、通信预算、共享资源及超预算行为 |
| 配置与装载 | 参数合法范围、相容组合、版本识别、更新原子性、失败恢复及误装载防护 |
| 验证依据 | 审查、分析或试验方法、目标环境代表性、模型适用性、测量误差和判据来源 |

不要把平均响应时间或百分位当作硬截止时间保证；不要把一次实测最大值当作有论证的最坏执行时间上界。检查要求是否已明确其依据，而不是在评审中自行推导保证。

## 判定边界

- 阈值、容差、响应期限和控制性能应追溯到系统分配或获准分析；缺失时提出待决事项，不凭常识补值。
- “安全模式”“保持输出”“复位”不是通用安全策略。检查该策略在具体任务条件下是否有定义及依据，不能替项目选择。
- 若需求在指定模型中可验证，但模型有效范围或系统分配依据缺失，记录证据限制；不能宣称实际飞行安全已经得到保证。
- 智能体可指出潜在不可行性或冲突，需要专业分析才能确认时，应明确“待领域分析”，不能假装完成控制稳定性或安全证明。

## 按软件类型裁剪

- 飞控、姿态控制：重点审查动态性能、模式、故障策略、数值及实时性。
- 机载或星载数据处理：重点审查时间一致性、标定、质量、误差、吞吐和存储。
- 航电平台与通信：重点审查协议、隔离、仲裁、资源竞争和故障传播。
- 航天任务管理：重点审查长时序、通信中断、自主权限、状态恢复和时间回绕。
- 地面测控：重点审查指令授权、有效期、防重放、人工确认、操作记录与链路异常。
- 试验支持软件：重点审查模型范围、实时性、故障注入、判定方法与证据完整性。

没有控制回路时，可将控制性能项标为不适用并给出理由；不能仅因软件在地面运行就认定它没有安全影响。

## 示例：识别真实歧义

原文：“主测量异常时应及时切换备用源。”

- 缺失：异常类型与检测条件未定义；若引用文件已有定义，先核对引用，不重复报告。
- 歧义：相同采样数据晚到时，按源采样时间判断可能已过时，按接收时间判断则可能有效。原文未规定时间语义时，两种实现会产生不同源选择结果。
- 不可验证：“及时”没有明确起止事件及期限，无法决定边界场景通过还是失败。
- 场景缺口：两个源均不可用时，如果仍在适用范围内，后续行为没有确定。
- 不应强加：不能因为存在上述问题，就要求使用某个特定状态机实现或自行设定切换阈值。
