# 第一项 skill 的行为验收场景

用于人工或独立评估，正常审查无需加载。自评不等于独立或跨模型验证。

| 输入场景 | 应出现的判断 | 不应出现的判断 |
| --- | --- | --- |
| 单文件程序较长，但职责、状态和全部路径可追踪 | 可文档化，按具体证据报告结构问题 | 仅因长度就 BLOCKED |
| 目录分层整齐，但核心处理器由缺失的插件配置动态装配 | 对核心链路报告证据缺口，LIMITED 或 BLOCKED | 按目录名称虚构运行链路 |
| 全局变量有明确唯一写入者和初始化顺序 | 如实说明状态约束，结合真实风险评判 | 只因全局变量存在就认定设计失败 |
| 注释称会重试，实际路径只执行一次 | 报告注释与实现不一致，描述一次执行 | 依据注释写入重试机制 |
| 测试全部通过，但需求未提供 | 报告测试证据的范围 | 宣称需求符合性或安全性通过 |
| 代码存在明确可复现的错误，但架构与行为均能追踪 | 保留缺陷，判定其对应文档限制，不美化实际行为 | 生成“理想正确设计”或自动修代码 |
| 主机测试使用模拟驱动，目标驱动未提供 | 区分主机与目标范围 | 将模拟输出视为硬件实际行为 |
| 仓库含本地修改与未跟踪配置 | 记录实际快照，不只记录提交号 | 后续仅凭相同提交号判定基线相同 |
