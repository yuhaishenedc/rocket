# 航空航天代码的专项审查

仅按软件职责和说明范围选择适用项。以下检查用于判断证据是否足以描述设计，不是安全认证、控制稳定性证明或全面代码正确性验证。

| 对象 | 追踪的证据与容易出现的缺口 |
| --- | --- |
| 周期与调度 | 任务入口、周期来源、优先级、多速率交换、时钟来源；仅见周期常量不能证明实际调度或截止时间 |
| 模式与控制权限 | 模式枚举、转换条件、故障与命令的优先级、权限仲裁、复位后的状态 |
| 测量与估计 | 单位、坐标、采样和接收时标、有效性、冻结或陈旧处理、状态初始化 |
| 控制算法 | 离散状态更新顺序、参数与查表来源、饱和、速率限制、数值边界、异常值处理 |
| 故障与恢复 | 检测、持续条件、锁存、降级、恢复与反复切换抑制的实际代码路径 |
| 输出与硬件 | 指令发布、驱动接口、总线映射、硬件限制；寄存器写入不能自动证明执行机构已动作 |
| 共享资源 | 中断、任务共享状态、同步与数据快照、内存和栈等资源约束的依据 |
| 生成代码与参数 | 上游模型、生成选项、后处理、参数版本、装载路径及有效配置；生成代码可读不等于模型含义已知 |
| 验证与平台 | 测试替身和实机实现的区别、主机与目标机差异、分析报告的实际适用基线 |

遇到无依据的阈值、坐标转换或模式策略，不要自行推断其工程理由。可以描述代码采用了什么值或规则，同时标明来源与适用性待确认。

发现潜在异常输出、竞争或超时风险时，给出证据和条件，并提交领域确认。不得仅从源代码宣称最坏执行时间、稳定裕度、容错等级或飞行安全。

地面测控和试验支持软件也应按接口与任务影响选择检查项；不因不在飞行器上运行而自动忽略权限、时标、配置及故障处理。
