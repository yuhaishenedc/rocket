# 系统测试规格与结果交接约定

约定版本：1。用于设计、执行与评估之间的交接，不限定测试框架。

## 1. 测试集身份与系统边界

记录测试集标识与版本、需求和接口版本、系统配置、被测边界、外部系统、真实与模拟组件、已知限制及评审状态。

区分目的：`CONFORMANCE`（需求符合性）、`REGRESSION`（经确认行为的回归）或 `EXPLORATORY`（探索）。回归用例若用于符合性判断，仍需明确规范性判据；探索用例不能计为符合性通过。

## 2. 每个用例

| 字段 | 内容 |
| --- | --- |
| 标识、版本、状态 | 例如 ST-001；DRAFT／READY／BLOCKED |
| 依据与目的 | 需求条款、验证义务、优先级依据、测试目的 |
| 适用边界 | 任务阶段、模式、构型、运行范围和排除事项 |
| 环境 | 实际系统、模拟组件、模型、参数、负载和依赖版本 |
| 初始状态 | 系统及外部环境状态、预置数据与启动过程 |
| 输入和故障 | 输入历史、注入对象、数值、时刻和持续条件 |
| 步骤 | 操作顺序、观测时点、重复或抽样策略 |
| 预期与来源 | 端到端输出、状态、允许和禁止行为、判据条款 |
| 指标计算 | 单位、时基、事件起止、窗口、容差、误差与统计判据 |
| 环境有效性 | 校准、同步、实时性、模型范围和数据完整性检查 |
| 安全与授权前提 | 设备约束、互锁、批准需求、中止与恢复，不适用需说明 |
| 证据 | 原始数据、事件、配置、采集状态、告警及版本标识 |
| 清理与隔离 | 恢复系统、清除注入、避免跨用例污染 |
| 未知与限制 | 阻断项、关联问题及结论不能推广到的范围 |

## 4. 执行记录要求

每次执行记录 RUN 标识、用例和需求确切版本、系统软件与二进制标识、参数及模型、平台和硬件、时钟与测量配置、初始条件、实际刺激和注入、完整输出及事件、指标计算版本、中止原因和原始证据位置。

记录环境健康数据：如时间同步、仿真超时、数据丢失、采集精度和设备校准。保护敏感信息，报告中只保留必要引用。

首次失败及后续重跑分别保留；参数或判据修改后建立新版本，不覆盖原执行结果。实际执行行为与计划不一致时，记录差异，交评估方判断是否影响有效性。
