# 单元测试规格与结果交接约定

约定版本：1。用 Markdown 表格或结构化文本记录，不要求专用解析器。评估方应使用用例的确切版本，不根据名称猜测判据。

## 1. 用例集身份

- 用例集标识、版本、作者或生成来源、评审状态。
- 设计说明、规范性条款、接口、代码与配置版本。
- 单元边界、包含和排除范围、已知问题。
- 测试目的的分类及其证据边界。
- 真实依赖、替身、平台、构建和运行前提。

## 2. 每个用例

| 字段 | 必填内容或明确的不适用说明 |
| --- | --- |
| 标识与版本 | 例如 UT-001，修订时保留身份并更新版本 |
| 目的与状态 | CONFORMANCE／CHARACTERIZATION／EXPLORATORY；DRAFT／READY／BLOCKED |
| 测试依据 | 设计或契约条款、位置、版本及预期的独立依据 |
| 被测单元 | 实际符号、接口、边界和配置 |
| 测试条件 | 要验证的一个明确义务，重要性及依据 |
| 前置与初始状态 | 初始化、共享状态、资源及前提约束 |
| 替身行为 | 依赖返回值、异常、回调、时钟和随机源规则 |
| 输入 | 确切值或可重建的数据生成规则、种子及分布 |
| 执行步骤 | 有序操作、必要的重复次数、观测时刻 |
| 预期 | 输出、状态、副作用、错误行为及其推导 |
| 比较规则 | 精度、容差、时间窗口、统计规则和来源 |
| 清理 | 状态恢复、资源释放及失败时清理 |
| 证据 | 实际值、断言、时间、日志及必要的替身调用记录 |
| 限制与问题 | 未知内容、阻断原因及关联问题编号 |

## 3. 覆盖与缺口

| 设计条款 | 条件或边界 | 用例及目的 | 预期依据 | 计划覆盖 | 未覆盖原因 |
| --- | --- | --- | --- | --- | --- |

不要用用例数量证明充分性；现状回归用例不能替代符合性用例覆盖。

## 4. 交给执行者的记录要求

每次执行应记录 RUN 标识、用例版本、实际代码或二进制及本地差异、设计和配置、框架与平台、替身版本、完整输入和随机配置、实际观测与时间、断言原始输出、退出或中止原因。

保存首次失败和所有重跑，不覆盖原始结果。结构覆盖数据应与同一被测构建关联。缺少的信息必须标为未知，不能由评估者补造。

本约定不授权执行测试；执行仍需符合用户任务范围和环境权限。
